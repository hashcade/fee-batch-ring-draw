# Project guidelines

- Write source, comments, scripts, and documentation in English.
- Keep README focused on this mod's current features, requirements, installation, configuration, Credits, and standard license. Do not include personal cheat lists, companion-cheat guidance, predecessor migration history, development/release workflows, or detailed implementation notes; keep engineering details in the existing docs instead. Preserve concise, accurate author/dependency attribution in Credits, following the other mods. Never remove Credits or License when simplifying README.
- Do not add personal cheat files, companion cheat directories, their tests, or their maintenance documentation to this mod repository. When the user requests changes to an external shared cheat file, edit that file only; do not copy it into the repository or release packages.
- Keep commits atomic. Do not release or install unless explicitly requested.
- Retain the existing ring transaction safety checks and Cobalt 1.31 ABI conventions.
- Scope local verification to the change; CI owns full regression checks.
- Model native menu inheritance accurately: BasicMenuItem has 27 virtual slots; MapBasicMenuItem adds flag/help/map-attribute slots 27-29; ConfigBasicMenuItem adds InitContent at slot 27. Preserve inherited initialization through both the plugin's clone and Cobalt's subsequent clone. Never fabricate extra base-class slots in fixtures. Select the actual native item type and constructor, and check only the interfaces that the feature uses.
- Facility AIDs must resolve through HubFacilityData.Get and its instance IsComplete; HubUtil.IsComplete accepts chapter CIDs only. Fixtures must distinguish these receivers and independently locked facilities, including the adoption barn.
- Adding draw choices requires real prefab row nodes before SetShowRowNum. Its native capacity check can reject a larger row count without reporting an error. Test the actual modeled node count/positions, not just the row-setter call.
- Keep one outdoor facility entry. It opens Facilities / Activities / Shops, with six / six / five destinations, retaining every existing shortcut. The arena belongs to Facilities, not Activities. Never put the categories directly into the outdoor menu or merge the destinations into a seventeen-entry scrolling list. Reuse native selection/help callbacks; do not add custom scrolling, row-pool expansion or forced arrow visibility for these short lists.
- Facility submenu B uses BasicMenu.Result CloseThis | SeCancel (513); never DeleteAll (32). Check flag semantics and the retained parent chain, not just an expected magic number. Keep inline help empty rather than duplicating the row title.
- Facility categories remain a side panel beside the outdoor menu: SortieSubMenuContent.Create (0x024EB420), native binding/suspension, row count, then SetTransformAsSubMenu (0x0245E330). Destinations use native HubMenuContent.Create (0x028B78C0) without submenu positioning; hide both ancestors while this page is open. Do not add a third side panel, post-build coordinate correction or custom scrolling. Native B disposal/resume restores the category and outdoor panels with their retained selections. Entering a facility hides only the destination page; original facility disposal restores only that page. Use single-menu CloseAnime (slot 22) and OpenAnime (slot 20), never OpenAnimeAll (slot 21). Test distinct content, category anchors, parent/child links, suspension, retained selection and visible/input-owning menus through every return path.
- All added HubMenuItem rows share menu_item::no_help, including collection in Somniel and post-battle exploration, the outdoor facility entry, categories and destinations. Do not borrow unrelated game text for inline subtitles. Keep Plugin Settings' separate help area unchanged.
- Cooking outcome names must use the native TasteData display-name resolver at 0x021DF0C0 for both the selected value and preview help. Raw Name at +0x28 is an MSBT key, not translated display text. Test actual key inputs (including MID_FOODRANK_Woman) with distinct translated outputs, not localized literals in the raw field or message-lookup identity stubs.
- Never modify user saves or installations. Supplied executable analysis is read-only.
- Check game version and Build ID at startup. Verify native instruction signatures offline with scripts/verify_game.py, not against runtime entries that Cobalt or other mods may already hook. Model Cobalt's preinstalled hooks in startup tests. Activity writes must not depend on original runtime instruction equality or suppress unrelated hooks/settings when a write fails.
- Do not add arbitrary instance-size, vtable-size, list-length, ancestry-depth, or selection-count limits, nor original callback-address equality gates. Keep actual null/index bounds, feature context, native eligibility and the requested normal transaction rules. Do not add collector inventory/capacity budgets.
- Run transactions synchronously on the original game menu thread.
- Preserve native prices, probabilities, acquisition records, achievements, and equipped rings. Unlimited shop stock applies to the armory, item shop and flea market, including sold-out unlocked goods; retain chapter/unlock checks, prices, inventory limits and one-time ownership rules for outfits/accessories. Override stock reads/decrements, not saved inventory or unrelated variables.
- Pin shop fixture MethodInfo arguments independently from the plugin allowlists and verify concrete native wrapper loads. FleaMarketData.SetupContentList uses metadata slot 0x062B8228; adjacent 0x062B8220 is RegistImpl and must not match the content-list override.
- Keep the game's original level display. Do not add internal or cumulative level information to the UI.
- Preview only a copy of RNG state; never advance or restore the live RNG to skip a full result.
- Stop before an unaffordable or unrecordable result. Never retry after an attempted transaction.
- Keep the original outer flow; bypass presentation before changing the scene, background, or title bar.
- Expose requested preferences through Cobalt's in-game Plugin Settings. Persist them automatically in an independent SD-card file, never custom game/save variables. One-shot resource targets and SP ally selection are transient UI state, not preferences. Keep batch creation at 300 by default and retain original one/ten choices. Do not add logs, result windows, or quantity dialogs.
- Integrate batch ring creation, batch melding, fast ring cleaning, fast fishing, fast perfect strength training, and repeatable cooking in one plugin. Plugin Settings is one flat list of thirty-three rows, led by EXP and SP multipliers, SP target/amount, money/fragments, three ingots and nine crystals, then general preferences, use counts, stock, minigames and cooking. Do not add group headers or submenus; Cobalt's original ConfigMenu owns scrolling, row capacity, lifecycle and selection behavior. Shop stock, ordinary-gift stock, repeat cooking, fast fishing, fast strength training and fast Wyvern Ride each have an independent default-on switch. Fishing nondecreasing uses is a separate default-on switch from fast fishing; hook only native use settlement, retaining rewards, records and unlocks. If the session is already exhausted, supply one remaining use on Somniel entry or when enabling it. Standard training defaults to ten, rewind to nondecreasing, and battle saves and personal outfits to on. Batch melding, ring cleaning and other unlisted conveniences retain their existing behavior.
- EXP and SP multipliers are independent and default to 1x, with 1/2/3/5/10 choices. EXP has one extra Max Level choice, labeled exactly 满级 in Simplified Chinese. It requires a positive native EXP reward and reaches only the current class cap with normal growth; never auto-reclass or maximize stats. Preserve normal and manually skipped EXP animations. Multiply rewards only once, keep SP eligibility and its 9999 cap, and leave skill books/global SP additions unchanged. Split large native AddExp calls only inside the original EXP settlement context, because vanilla increments at most one level per call.
- Include the explicitly requested food-list stock bypass and inventory-free ordinary gifts. Scope gift changes to the original ordinary-gift menu and settlement; never bypass global item inventory, special relationship prerequisites, or plot checks.
- Ordinary Wyvern Ride finishes after its opening at the current difficulty's native SSS boundary. Retain the original ending, record updates, rewards and eligibility. Do not fabricate target counts, perfect scores, unlocks, or additional attempts; preserve event/test/pause/retirement paths.
- Confirmed batch melds skip presentation before header/footer/background changes. Preserve native settlement and outer resource cleanup; do not synthesize skip-button input.
- Skip presentation battles in ordinary and paid Emblem training. Automatically skip messages only within native C/B/A support or Emblem bond calls, including paid training. Preserve native calculation, EXP, growth, configured allowances, fragment cost, script execution, viewed/completion callbacks, achievements and cleanup. Story and Pact Ring conversations remain unchanged. Do not add continuous resource refills. Requested resource amounts use one-shot native setters only. Do not install or release without an explicit request.
- Automatic ordinary supports settle directly through UnitReliance.LevelUp and native MyRoomRelianceCallSequence.UpdateAchive, only after native CanLevelUp permits a C/B/A step. Run once per unordered pair per entry scan, only in the Somniel (sequence 4), on idle scene arrival or exploration-menu opening. Do not open selectors, clone support menus, synthesize A/B input, globally mutate CanLevelUp, force support EXP/ranks or write custom viewed flags. Keep native linked-Emblem updates and protagonist-specific achievement/friend-list rules. UpdateAchive's unused receiver is proven by its full offline-pinned body; verify the rank advanced before invoking it. Post-battle exploration and Pact Ring events remain untouched.
- Exploration collection uses the original menu on its game thread. Collect only generated pending sources, retain native donation/adoption rules, and never mark unrelated interactions complete. Do not add inventory/resource/convoy/species capacity budgets or hide the entry because inventory is full; native reward and capture functions own their limits. Ordinary villager gifts must pass the native result-index/access-count gate; only their native conversation counter is consumed. Collection must not consume support/story interactions or generate new drops.
- Exploration collection must enter CommonRewardSequence.CreateBindForWell once, with its original TitleMID key. Let the native sequence load/wait for resources, grant rewards, display results, handle overflow and unload. Never directly open an unloaded reward dialog or manually grant before this sequence.
- Collection retains the original outdoor menu instance and selection. Hide only its panel while native reward results run; wrap the reward sequence's original OnDispose to restore it after cleanup. Return only the decide sound, not CloseThis/DeleteAll. Adoption-only batches leave the menu open without creating an empty reward dialog.
- Document Nintendo Switch installation before emulators. Use standard MIT attribution.
- One-shot resource rows use the native settings CustomCall input path, including Pad.IsTrigger(A), not a normal-menu ACall assumption. Left/right previews only; A applies the selected row once with decide sound and no close bits. Preserve native selection/InitContent/B/scrolling through Cobalt's second clone. Values retain tails and clamp at the actual limits. All-SP means absolute assignment to joined Player/Absent allies, not an increment; mixed values must not impersonate one ally. Reset pending SP on target changes and all drafts on reopening; never persist drafts/ally selection or install polling hooks. Idle numeric-row callbacks must not enumerate units, read inventories or allocate.
